# PWA: выполненные проверки и ручной чек-лист

Дата: 24 октября 2026 года. Целевое устройство: iPhone 17, iOS 26.6.2.

По уточнению пользователя Codex реализует PWA и выполняет статические проверки. Ручную приёмку Safari и установленного приложения пользователь проводит сам. Автоматические браузерные тесты, отдельный QA-стенд и HTTPS-инфраструктура в эту задачу не входят.

## Что реализовано

- Manifest с названием «Квартирка», русским языком, стабильным id и standalone-запуском.
- Обычные иконки 192/512, maskable-иконка, Apple touch icon 180 и SVG favicon.
- Генерируемый Workbox service worker для production build; precache только оболочки и статических ресурсов.
- API исключён из навигационного fallback и не имеет правил runtime-кеширования.
- Предложение новой версии, действие «Позже» и подтверждение перезагрузки.
- Запрет обновления во время mutation и отказ от принудительной активации при других открытых клиентах того же origin.
- Проверка новой версии при возвращении приложения в foreground, восстановлении сети и раз в час в видимом окне.
- Верхние и боковые safe-area отступы документа; существующий нижний отступ мобильной навигации сохранён.

Используется vite-plugin-pwa 2.0.0 с workbox-window 7.4.1. Версии Vite, React и остальных прямых зависимостей не менялись. Совместимость Node.js и Vite проверена по метаданным официального registry перед установкой. Тестовая зависимость Playwright, начатая до изменения объёма задачи, удалена; её нет в итоговом package.json и lock-файле.

Браузерные сценарии, CRUD, обновление A → B и физический iPhone на этом этапе не проверялись. Эти строки не являются успешной runtime-приёмкой.

## Перед ручной проверкой

1. Использовать production-сборку, а не Vite dev server. Для локального просмотра на компьютере нужны pnpm build и pnpm preview.
2. На iPhone открыть HTTPS-адрес, по которому размещена эта сборка. Backend должен работать через /api/v1 на том же адресе. Локальный http://192.168… годится для просмотра интерфейса, но не для проверки service worker. Исключение localhost относится к устройству, на котором открыт браузер. [Требования PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).
3. Проверять в обычном режиме Safari. Записать адрес и дату проверки.
4. Для создания/редактирования использовать собственные явно тестовые записи. Не удалять реальные покупки или пополнения ради проверки. Если нет тестовых данных, сначала пройти установку, навигацию и темы.
5. Для обновления потребуется позже разместить вторую, действительно отличающуюся сборку на том же адресе. Обычный reload без новой сборки не проверяет обновление.

Пока нет подходящего HTTPS-адреса, мобильные PWA-сценарии остаются непроверенными. Этот документ не предполагает, что тестовый сервер уже существует.

## 1. Установка

- [ ] Открыть адрес приложения в Safari при работающей сети.
- [ ] Войти в аккаунт и дождаться загрузки страницы.
- [ ] Нажать «Поделиться»; при выбранном расположении панели Safari кнопка может находиться внутри меню страницы.
- [ ] Выбрать «На экран Домой». Если пункта нет, проверить список действий в меню «Поделиться».
- [ ] Оставить название «Квартирка» и включить «Открывать как веб-приложение», если переключатель показан. Нажать «Добавить».
- [ ] Вернуться на домашний экран и нажать новую иконку.

Ожидается: зелёная иконка с белым домом; приложение открывается отдельным окном без обычной адресной строки Safari. Если потребовался вход, выполнить его внутри приложения. [Инструкция Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios).

## 2. Повторный запуск и фон

- [ ] Открыть раздел «Покупки» и дождаться данных.
- [ ] Перейти на домашний экран, затем вернуться в приложение.
- [ ] Открыть переключатель приложений, закрыть «Квартирку» смахиванием и снова открыть её иконкой.

Ожидается: приложение запускается без белого экрана; действующая сессия позволяет загрузить данные. Сохранение последнего маршрута после полного закрытия не является обязательным условием — стартовый маршрут ведёт к накоплениям.

## 3. Навигация и прямые ссылки

- [ ] По нижнему меню последовательно открыть «Накопления», «Покупки» и «Профиль».
- [ ] В Safari отдельно открыть адрес приложения с путём /purchases, затем /profile; обновить каждую страницу.
- [ ] На покупках выбрать комнату, затем обновить страницу в Safari.

Ожидается: страницы открываются, данные загружаются, фильтр сохраняется в URL. Без сессии защищённая ссылка ведёт на вход. Safari и приложение с домашнего экрана могут иметь разные состояния хранилища; постоянная синхронизация их темы и отдельных сессий не требуется.

## 4. Темы и экран iPhone

- [ ] В «Профиле» выбрать тёмную тему, закрыть приложение и открыть повторно.
- [ ] Проверить все три раздела в тёмной теме, затем повторить в светлой.
- [ ] Прокрутить длинный список до конца; повернуть телефон горизонтально и обратно.

Ожидается: тема сохраняется внутри приложения; текст читается, вырез экрана и нижний системный индикатор не закрывают важные элементы, горизонтальной прокрутки страницы нет.

## 5. Формы и экранная клавиатура

- [ ] Нажать «Добавить пополнение», выбрать поле суммы, комментарий и дату.
- [ ] Проверить, что поля и кнопки доступны при открытой клавиатуре и после прокрутки формы.
- [ ] Нажать «Отмена»; перейти в «Покупки» → «Добавить покупку» и повторить проверку полей.

Ожидается: клавиатура не делает форму недоступной; ввод не прыгает и не пропадает сам. Отмена ничего не сохраняет.

## 6. Сохранение и регрессия

- [ ] Создать тестовое пополнение с копейками, перезапустить приложение и проверить сумму/комментарий.
- [ ] Изменить и удалить только эту тестовую запись; убедиться, что показатели пересчитались.
- [ ] Создать тестовую покупку без цены: ожидается «Цена не указана».
- [ ] Изменить её цену, комнату и статус; проверить сводку и фильтрацию.
- [ ] Открыть безопасную внешнюю ссылку товара, затем вернуться в приложение.
- [ ] Удалить только созданную тестовую покупку.

Ожидается: операции сохраняются на backend и остаются после перезапуска; смена фильтра не меняет общую сводку.

## 7. Потеря сети при открытой форме

- [ ] При работающей сети открыть форму нового пополнения и ввести тестовые данные.
- [ ] Включить авиарежим и отдельно убедиться, что Wi-Fi тоже отключён: iPhone может сохранить Wi-Fi включённым в авиарежиме.
- [ ] Нажать «Сохранить пополнение».
- [ ] Вернуть сеть, но пока не нажимать сохранение ещё раз.
- [ ] Проверить, что запись не отправилась сама. Затем осознанно повторить сохранение и проверить результат.

Ожидается: без сети форма показывает ошибку и сохраняет поля; сообщения об успешном сохранении нет. Возвращение сети не отправляет mutation автоматически.

Если связь оборвалась уже после отправки, сначала проверить список: backend мог сохранить запись, даже если ответ не дошёл. Ручной повтор без проверки в таком случае может создать дубль.

## 8. Запуск без сети

- [ ] Сначала онлайн открыть приложение и основные разделы, дождаться загрузки.
- [ ] Отключить мобильную сеть и Wi-Fi, полностью закрыть приложение и открыть его иконкой.
- [ ] Вернуть сеть и нажать повтор загрузки, если он показан.

Ожидается: загружается оболочка и понятное сообщение об отсутствии связи/недоступности данных. Наличие самих покупок и накоплений после холодного offline-запуска не требуется. После восстановления связи загрузка снова работает. Первый запуск без предварительного кеша не обязан открываться офлайн.

## 9. Выход и смена пользователя

- [ ] Онлайн открыть «Профиль» → «Выйти из аккаунта».
- [ ] Закрыть приложение и снова открыть его иконкой.
- [ ] Войти вторым аккаунтом, если он доступен для проверки.

Ожидается: после выхода требуется вход; профиль показывает вошедшего пользователя. Накопления и покупки общие, поэтому совпадение этих данных у двух пользователей нормально.

## 10. Обновление: потребуется новая сборка

Этот сценарий выполняется, когда на том же HTTPS-адресе уже размещена следующая версия. До этого отметить «не проверено», а не «пройдено».

- [ ] Оставить старую версию открытой. Открыть форму и ввести текст без сохранения.
- [ ] После размещения новой версии перейти на домашний экран и вернуться в приложение.
- [ ] Убедиться, что форма не перезагрузилась и текст остался. Завершить работу с формой: сохранить её или осознанно отменить.
- [ ] В предложении новой версии нажать «Позже»: текущая страница должна продолжать работать.
- [ ] Ещё раз уйти на домашний экран и вернуться, затем нажать «Обновить».
- [ ] В подтверждении нажать «Отмена»: приложение остаётся открытым.
- [ ] Повторить «Обновить» → «Перезагрузить и обновить», когда несохранённых данных нет.

Ожидается: новая версия запускается без цикла перезагрузок; сессия и выбранная тема сохраняются в том же контексте. Пока идёт сохранение, кнопка обновления недоступна. Система может сама активировать ожидающую версию после закрытия всех старых окон — это нормальный lifecycle service worker.

## 11. Две вкладки при обновлении

Удобнее выполнить в двух вкладках Safari одного сайта. Установленное приложение может иметь отдельное хранилище, поэтому связка Safari + иконка не всегда проверяет один и тот же service worker.

- [ ] В обеих вкладках открыть старую версию. Во второй открыть форму и ввести текст.
- [ ] После размещения новой сборки в первой нажать «Обновить» → «Перезагрузить и обновить».
- [ ] Убедиться, что приложение предлагает закрыть другие окна, а текст второй вкладки не потерялся.
- [ ] Сохранить/отменить вторую форму, закрыть вторую вкладку и повторить обновление в первой.

Ожидается: принудительное обновление при нескольких клиентах не происходит; после закрытия лишней вкладки можно обновить оставшуюся.

## Как записать результат

Для каждого раздела: «пройдено», «не пройдено» или «не проверено». При проблеме записать шаг, ожидаемый и фактический результат, состояние сети и контекст — Safari либо приложение с иконки. Скриншот полезен, но без паролей и других секретов.

Статус на момент передачи: реализация и статические проверки завершены; ручная приёмка пользователем ещё не проведена. Это завершает уточнённый объём работы Codex, но не является подтверждением полной PWA-приёмки на iPhone.
